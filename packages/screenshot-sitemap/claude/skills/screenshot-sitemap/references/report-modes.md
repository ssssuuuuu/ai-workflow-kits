# Report Modes — 산출물 3가지 모드

step 11(종합 보고서)의 출력 형식 선택 기준. 내용(트리·진단·로드맵)은
동일하고 **구성과 문법**이 달라진다. 사용자가 형식을 지정하지 않으면
실무 상세 모드로 내되, "상급자/경영진 보고", "결재 문서", "심플하게" 같은
신호가 있으면 해당 모드로 전환한다.

## 모드 1 — 실무 상세 (기본)

분석가·실무자가 검증하며 읽는 문서.

- 전 주장에 근거 등급 태그: `[관찰] [문서] [추정] [확인필요]`
- ID 체계(P-xx, IA-xx, REQ-xx) 전면 노출, 상호참조 표
- 방법론·근거 한계를 본문 앞부분에 배치
- 심각도: `critical / major / minor / quick-win`

## 모드 2 — 경영 보고 (executive)

의사결정자가 5분 안에 읽는 문서. **모드 1을 그대로 내면 안 된다** —
분석자의 문법(ID·태그·방법론 우선)은 보고받는 사람의 문법이 아니다.

구성 순서:

1. **결론 요약** — 3문장. 무엇이 문제고, 무엇을 승인해달라는지가 첫 화면
2. **핵심 수치** — 3~5개의 큰 숫자 (예: "UI 체계 4종 병존", "품질평가 양호 0/8")
3. **방치 시 리스크** — 문제를 비용 언어로 번역해 3버킷: 생산성 손실 /
   운영·업무중단 리스크 / 규제·감사 리스크
4. **개선 방향** — As-Is → To-Be 대비표 (분석 축이 아니라 "무엇이 달라지나")
5. **추진 로드맵** — 단계 × 기간 × 내용 × 기대효과 (티켓 나열 금지)
6. **의사결정 요청사항** — 명시적 승인 요청 2~3건, 각각 소요 자원 표기
7. **성과 지표** — 측정 가능한 KPI

규칙:

- 본문에서 ID·근거 태그·분석 용어 제거, 평문으로 번역
- 상세 진단은 전부 **접이식 부록(별첨 A~G)** 으로 격하 — 내용은 버리지 않는다
- "근거가 뭐냐"는 질문에 해당 부록을 펼쳐 답할 수 있는 구조

## 모드 3 — 심플 문서형 (결재/공공기관 스타일)

국내 컨설팅·행정 보고 문서 관행.

- 표제부: 중앙 정렬 제목 + 이중 밑줄, 보고 목적/대상/근거 메타 표
- 항목 체계: `Ⅰ. Ⅱ. Ⅲ.` 로마자 장 + `□` 소항목 + `·` 세부의 3단 위계
- 색상 최소화: 단색(네이비 계열) 1색 + 심각도만 유채색
- 심각도는 한글로: `상 / 중 / 하`
- 카드·칩·배지 등 장식 UI 제거, **정형 표 중심**
- 로드맵: 단계/기간/내용/기대효과 표. 요청사항: 구분/요청/사유/소요 표
- 부록은 "별첨 A~G" 명명

## 공통 불변 규칙 (모드와 무관)

- 근거 없는 주장 금지 — 모드 2·3에서 태그를 숨기더라도 부록에는 유지
- 화면 출처(`파일 @ mm:ss`) 추적 가능성 유지
- "확인필요" 항목을 확정 사실처럼 쓰지 않기 — 잠정 표기
- 클라이언트 내부 자료가 포함된 보고서는 공개 저장소에 커밋하지 않는다
